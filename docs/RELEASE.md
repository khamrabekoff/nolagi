# Выпуск новой версии и любые изменения: что обновить везде

Правило: если меняется программа — новая версия, новая или убранная функция, другие цифры, другой вид окна — **в том же изменении** обновляются все места, где об этом написано или показано. Сайт, README и тексты не должны расходиться с программой.

## Чек-лист

### Код и репозиторий
- [ ] `app/src/App.cs` — `Version = "X.Y.Z"`.
- [ ] `CHANGELOG.md` — раздел новой версии.
- [ ] `README.md` — таблица вкладок и описание возможностей; скриншоты в `docs/images/`, если изменился вид окна.
- [ ] `PRIVACY.md` — если программа стала хранить или отправлять что-то новое.
- [ ] `THIRD_PARTY_NOTICES.md` — если взят чужой код.
- [ ] Описание и темы репозитория на GitHub (About).

### Сайт (`site/`)
- [ ] `index.html` — карточки возможностей, мифы, раздел «Чего не делает», вопросы **и их копия в JSON-LD** (`FAQPage`), цифры вроде «около 100 настроек».
- [ ] Запасной текст версии (`id="ver"`) — сама версия подтягивается с GitHub, но запасной текст тоже обновить.
- [ ] `site/img/` — скриншоты, если изменился вид окна. Делать из dev-сборки (`app/build.ps1 -Dev`), без тестовых данных и личной информации.
- [ ] `sitemap.xml` — дата `lastmod`.

### Выпуск
- [ ] PR → зелёный CI → мерж (не `--auto`: в репозитории нет обязательных проверок, мерж происходит сразу).
- [ ] Сборка `dist\Nolagi.exe` из `main`, GitHub Release `nolagi-X.Y.Z` с описанием и SHA-256.
- [ ] Публикация на сервер (`publish_release`) с тем же описанием; проверить, что `/api/v1/update` отдаёт новую версию и хеш совпадает.

### Продвижение
- [ ] Тексты руководства Steam и статьи для Хабра — если в них упомянуто изменённое (функции, горячие клавиши, цифры).
- [ ] Уже опубликованные руководство и статья — обновить и их.

### Проверка
- [ ] Поиск по репозиторию старого номера версии и старых цифр: `git grep -n "1.3.0"`, `git grep -n "около 100"` и т.п.
